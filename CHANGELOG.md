## [0.2.0] - 2026-10-31

### Added

- Second dynamics backend on orocos KDL (`KdlModel`: kdl_parser chain `base_link → tool0`,
  `ChainIdSolver_RNE`, `ChainDynParam`, `ChainJntToJacSolver`) behind a common `DynamicsModel`
  interface that `PinocchioModel` now implements; read-only `dynamics_backend`
  (`pinocchio` | `kdl`, default `pinocchio`) and `gravity_z` (default −9.81) parameters on both
  controllers; `sim.launch.py dynamics_backend:=kdl`.
- `test_dynamics_equivalence`: both backends on 200 random states at 0 kg and 1 kg payload
  (gravity and RNEA within 1e-6 N·m, M within 1e-6, J within 1e-9); KDL controller tests on
  mock hardware; a test that the worlds' gravity equals `gravity_z`.
- `bench_dynamics_timing` (C++) and `scripts/bench_dynamics_timing.sh`: per-call median / p95
  of gravity() and rnea() on both backends and their share of the 2 ms cycle,
  `results/dynamics_timing.csv`, a table in `docs/results.md`; CI runs it as a 1 000-call smoke
  test.
- `scripts/lib/heavy_processes.sh`: `regenerate_all.sh` and the timing benchmark refuse to
  start next to a simulator, build, pip install or training run.
- Computed-torque law on the tracking controller (`control_law: pid_ff | computed_torque`,
  `ct_omega`, `ct_zeta`; runtime-switchable, either backend), `test_computed_torque`
  (closed loop against an exact-model plant), and a computed-torque leg in the smoke test.
- `bench_tracking` runs PID, PID + RNEA FF and computed torque (`--variants`) and stamps the
  dynamics backend; `make_results.py` renders whichever variants the CSV holds.
- `TcpJogController` (mode `jog`): TCP twist on `~/twist` → damped least squares with
  manipulability-scheduled damping, joint speed / acceleration / position limits as uniform
  scalings, 0.1 s deadman, PID + RNEA joint loop on the integrated reference, `~/jog_state`
  with sim-time stamps; `test_dls`, mock-hardware tests and a jog leg in the smoke test.
- `bench_jog` and `scripts/bench_jog.sh` (command-to-motion latency, velocity tracking and stop
  time of the jog controller). The benchmark is written but its numbers are not yet published:
  `regenerate_all.sh` does not run it and `results/` has no jog CSV.
- The smoke test runs all three effort controllers in Gazebo (tracking reaches its goal with
  each law, hand guiding holds still, a streamed twist moves the arm and the deadman stops it),
  and CI runs it on both backends.
- Between-run spread of the tracking benchmark: five runs of the same code on 31 Oct
  (`results/runs_2026-10-31/`, one CSV per run, load average logged), reported by
  `make_results.py` as a min–max range on the feedforward and computed-torque rows and as a
  run-to-run table in `docs/results.md`, with a per-joint RMSE / RMS(q̇_des) row.
- GIFs regenerated by `scripts/record_gifs.sh` with captions burned into the frames:
  `hero.gif` (hand guiding with a visible push, correct payload model against a 1 kg model
  error), `tracking.gif` (PID alone against PID + feedforward with the live worst-joint error)
  and `jogging.gif` (a straight-line TCP move, then an approach to the wrist singularity).
  `record_mode --scene hero|tracking|jogging` records the takes through the controllers' normal
  interfaces (it replaces `--mode track|handguide`), and the new `scripts/compose_gifs.py` draws
  the panels, the push arrow, the tool traces and the live numbers from the recorded data.
- `docs/what_broke.md` (draft): a first-person section on the timing offset between reference
  and state, one section per failure item, the bugs fixed along the way, and an appendix of
  hand-recorded runs that no script regenerates, each with its date and source.
- `docs/controllers.md` "Gains and bandwidths": the shipped gains read back as bandwidth and
  damping ratio per joint, with the explicit-loop margins.
- CI can be started by hand (`workflow_dispatch`).

### Changed

- README rewritten for three kinds of reader: a one-sentence summary and the hero GIF on the
  first screen, "What this is", "See it", "Run it", "How it works" with a diagram, "Results in
  one breath" with a simplified headline table and two charts, and the thirteen failure items
  in four groups with a sentence or two each. The full tables moved to `docs/results.md`, the
  equations and backend details to `docs/controllers.md`, and the long failure explanations to
  `docs/what_broke.md`.
- The headline states PID + feedforward and computed torque as a range over the five runs, two
  orders of magnitude below PID alone, instead of one sub-millirad number with a within-run
  standard deviation; the hand-guiding hold force is described as equal to Δm·g by
  construction (a placement check, not a measurement).
- The published single-run tables are the 31 Oct regeneration, so the tables and the spread
  come from the same day.
- The run-to-run changes in the feedforward numbers are attributed to a run-dependent timing
  offset between reference and measured state (within a run, RMSE divided by RMS reference
  velocity is the same on all six joints), not to CPU load, which the recorded runs contradict.
  The README, `docs/results.md`, `docs/what_broke.md` and the script comments say so.
- `make_results.py` writes no hard-coded prose that states a number.
- A runtime payload change no longer modifies the model inside `update()`: a model with the new
  payload is built in the parameter callback and swapped into the realtime loop through a
  `RealtimeThreadSafeBox` (needed for KDL, whose solvers are rebuilt; same path for Pinocchio).
- `regenerate_all.sh` takes the machine's heavy, build and gazebo locks, in that order, and
  regenerates the timing table first.
- The tracking table was re-run with all three laws on one path.
- Build logs are no longer tracked; numbers that only they held are in the appendix of
  `docs/what_broke.md`.

### Removed

- `docs/assets/mode_track.gif` and `docs/assets/mode_handguide.gif`, replaced by the GIFs
  above.

### Fixed

- Documentation corrections from the 31 Oct review:
  - The real-UR paragraph: the UR driver exposes an effort command interface on PolyScope
    ≥ 5.23 / 10.10 and `ur_controllers` ships freedrive and twist controllers, so hand guiding
    and jogging have stock baselines on a real UR; what changes is the `direct_torque`
    keep-alive, friction compensation and latency.
  - The gain comments (`controllers.yaml`, `docs/controllers.md`): the wrist PD loops run at
    36–44 rad/s with ζ = 0.72 on wrist_2, not critically damped at 30 rad/s, so computed torque
    and PID + feedforward are compared at roughly equal stiffness on the base joints only.
  - Failure items: wrist_3 is the worst joint because of the timing floor, not a stability
    limit (K_d·Δt/M is far below one); the speed-cap fallback brakes at full torque instead of
    holding gently; the claim that PID-only rows did not move between runs was an artefact of
    the worst-joint metric.
  - New failure items: no stale-state or NaN handling in any controller; the speed-cap fallback
    is a full-torque brake; the max-error statistic is unstable because the trapezoid steps the
    desired acceleration at segment corners.
  - The damped-least-squares comment (`dls.hpp`): the schedule is Chiaverini's form on
    Yoshikawa's manipulability, not Nakamura and Hanafusa's, and the manipulability carries the
    length unit.
  - Numbers that no script produces moved to the appendix of `docs/what_broke.md`; references to
    untracked log files removed from code comments and docs.
- CI: `ur5e_teaching_bench` declares pytest through `extras_require`; the container's
  setuptools ignores `tests_require`, so colcon found no tests and CI failed.
- CI runs its container with host network and IPC, as the devcontainer does.
- `bench_camera.sdf` is well-formed XML (a `--` inside a comment).
- The controller polls in `sim_session.sh` and `ci_smoke.sh` are bounded by `timeout 10`: an
  orphaned poll once outlived its script and kept the machine-wide locks it had inherited. Every
  publish and poll in the smoke test is bounded, and its one-shot trajectory publisher stays
  alive until delivery.

## [0.1.0] - 2026-10-28

### Added

- Repository skeleton: MIT license, Lyrical Dockerfile and devcontainer, GitHub Actions CI that
  builds the image in the job and runs build, lint, tests, a results-consistency check and a
  headless Gazebo smoke test; pre-commit with ruff, clang-format (ROS 2 style), yamllint and
  markdownlint.
- `ur5e_teaching_bringup`: UR5e xacro overlay (position/velocity/effort command interfaces,
  wrist force/torque sensor as a ros2_control sensor, Gazebo-only payload link with xacro
  `payload_mass`), `bench.sdf` (DART, 1 ms, ForceTorque, ApplyLinkWrench), `bench_camera.sdf`,
  `sim.launch.py` (headless by default, `mode:=track|handguide`), `mode.launch.py`, controller
  configuration at 500 Hz.
- `ur5e_teaching_controllers` (C++17 ros2_control plugins, Pinocchio dynamics from the URDF):
  - `PidFfTrajectoryController`: effort; trapezoidal re-profiling under per-joint velocity and
    acceleration limits; PID with conditional-integration anti-windup; URDF torque limits;
    RNEA feedforward on the desired state, switchable at runtime.
  - `GravityCompHandGuidingController`: effort; g(q) + optional Coriolis, viscous damping,
    friction hook, runtime payload mass/CoM, joint-limit repulsion, speed cap that deactivates
    the controller with an error.
  - `PinocchioModel` wrapper and gtest cases (profiles, limits, PID, rigid-body identities on
    the UR5e URDF, controller_manager integration on mock hardware).
- `ur5e_teaching_bench` (Python): strict conflict-aware `mode_manager`, `bench_tracking`,
  `bench_handguide`, `record_mode`.
- Scripts: `ci_smoke.sh`, `bench_tracking.sh`, `bench_handguide.sh`, `record_gifs.sh`,
  `make_results.py` (tables and the README headline sentence from the CSVs),
  `regenerate_all.sh`, `build.sh`.
- Docs: README, `docs/results.md` (generated), `docs/architecture.md`, `docs/controllers.md`,
  a `docs/what_broke.md` placeholder; first benchmark results, figures and mode GIFs.

### Fixed

- Effort controllers no longer write zero torque on deactivation; doing so dropped the arm under
  gravity for one cycle at every hand-over between controllers.
- Runtime parameter changes are adopted without blocking the realtime loop and only as a whole
  set with correctly sized per-joint arrays; trajectories with NaN/Inf, out-of-limit targets or
  a stale start are rejected; trajectories are never freed in the realtime loop.
- Simulated gravity set to 9.81 m/s² to match Pinocchio (SDF defaults to 9.8).
- Hand-guiding damping raised so a payload-model error cannot carry the arm to the floor within
  two seconds; the hand-guiding controller falls back to the tracking controller on a speed-cap
  trip.
- The hand-guiding hold force is measured statically (converged tracking hold torque minus the
  hand-guiding model torque, through J⁻ᵀ), and drift over 1 s.
- Work around two failures of the stock `ur_sim_control.launch.py` on Lyrical (no controller
  parameters reach the controllers; duplicate robot spawn when Gazebo boots slowly) in
  `sim.launch.py`.
